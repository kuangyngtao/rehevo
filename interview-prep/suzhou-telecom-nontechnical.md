# 苏州电信研发技术类暑期实习生 - 非技术面试准备

> 使用方式：这份文档用于准备 HR 面、主管面和综合面。  
> 核心目标是让你显得稳定、真诚、匹配岗位、有培养价值，而不是只会堆技术词。

## 0. 非技术面试的核心策略

### 0.1 你要传递的人设

你的最佳定位：

> 通信背景扎实，学习能力强，愿意做工程落地，对 AI 应用和 Java 后端有实践，对电信行业有天然兴趣和理解。

不要把自己包装成：

- 只想做大模型算法研究的人。
- 只想做前沿 Agent，不愿意做业务系统的人。
- 只想找一份暑期实习，不关心行业的人。
- 什么都很精通的人。

### 0.2 面试官担心什么

HR 或主管可能会担心：

- 你是不是只想刷一段实习经历。
- 你是不是研究方向偏通信，工程开发能力不够。
- 你是不是只想做 AI，不愿意做普通开发、测试、联调。
- 你是不是对运营商节奏和业务场景不了解。
- 你是不是简历项目写得很深，但实际讲不清楚。

你的回答要围绕这些担心逐个化解：

- 我愿意从业务系统开发和技术支撑做起。
- 我有 Java 和 AI 应用项目，不是只做理论研究。
- 我知道运营商研发技术类岗位更偏工程落地和产数业务。
- 我能接受需求沟通、文档、联调、测试验证。

## 4. 项目讲述的非技术版本

### 4.1 AI 智能评测平台怎么讲

不要上来就讲一堆技术名词。先讲业务价值：

> 这个项目解决的是 AI 面试辅助场景。用户可以上传简历，系统自动解析和评估；也可以进行模拟面试和语音面试；还可以上传资料形成知识库，通过 RAG 做问答。它本质上是一个把 AI 能力嵌入业务流程的系统。

如果 HR 问“这个项目有什么难点”：

> 难点不是简单调用大模型，而是怎么把不稳定的大模型能力变成稳定的业务流程。比如文档解析可能失败，模型输出格式可能不稳定，分析任务耗时比较长，语音交互有延迟。所以我在项目里做了异步任务、状态流转、失败重试、结构化输出和降级处理。

如果问“和电信有什么关系”：

> 这个项目里的能力可以迁移到企业知识库问答、政企文档助手、智能客服、员工培训测评、工单问答等场景。这些都和电信的产数业务、内部信息化和政企服务有关。

### 4.2 MiniClaw 怎么讲

业务化表达：

> MiniClaw 是我做的本地 AI Agent 平台。它不是单纯聊天，而是让大模型可以拆解任务、调用工具、读取文件、执行命令、搜索信息，并且在执行高风险操作前做权限确认。

如果 HR 问“这个有什么用”：

> 它可以理解成智能工作助手的底层探索。比如内部运维助手、研发助手、资料整理助手，都需要模型调用工具、管理上下文、处理长任务和控制风险。我通过这个项目主要学习 Agent 工程化。

如果问“风险怎么控制”：

> 我设计了工具风险分级和人工审批。比如读取信息是低风险，写文件或执行命令就是高风险，需要用户确认。同时保留日志和结果汇总，避免模型自己乱操作。

### 4.3 科研项目怎么讲

业务化表达：

> 科研项目主要和物联网、边缘智能和语义通信有关。简单说，就是在不同业务接入网络时，先识别业务类型，再根据端侧、边缘和云端的资源状态做协同处理，减少带宽占用、降低时延。

如果问“和电信有什么关系”：

> 电信有大量网络、物联网和边缘计算场景。我的科研项目虽然偏实验室研究，但里面的业务识别、端边云协同和语义传输，和运营商的云网融合、边缘智能、网络资源调度有一定关联。

## 8. 行为面试 STAR 例子

### 8.1 学习能力

S：你原本是通信背景，但想做 AI 应用和 Java 后端。  
T：需要补齐 Spring Boot、数据库、Redis、RAG、Agent 等能力。  
A：通过项目驱动学习，先做 AI 智能评测平台，再做 MiniClaw，把后端接口、异步任务、向量检索和工具调用串起来。  
R：形成了两段可以讲清楚链路的工程项目，也能和通信背景结合投递研发技术类岗位。

回答版：

> 我觉得我的学习能力主要体现在从通信背景扩展到 AI 应用开发。最开始我对 Java 后端和 RAG 工程并不熟，但我用项目驱动学习，把 Spring Boot、Redis Stream、pgvector、Spring AI、Agent 工具调用这些技术串起来。现在虽然不敢说很资深，但已经能讲清楚完整链路和技术取舍。

### 8.2 解决问题

S：AI 项目中模型输出不稳定。  
T：需要让后端能稳定解析和展示结果。  
A：设计结构化输出、失败重试、错误原因注入、降级处理。  
R：避免单次模型异常导致整个流程不可用。

回答版：

> 大模型项目里一个明显问题是输出不稳定。比如要求它返回 JSON，它可能会多输出解释文本，导致解析失败。我处理方式是明确 schema 和字段说明，失败时把错误原因加入修复提示词让模型重新输出，同时设置降级兜底，避免整个流程卡死。

### 8.3 团队协作

科研项目：

> 在科研项目里，我需要和同学配合，有人负责模型，有人负责通信和设备环境。我主要参与流量采集、Jetson Orin 环境、设备通信和实验验证。这个过程中我会把环境配置、日志和问题记录下来，方便其他人复现实验。

### 8.4 抗压

> 我抗压的方式不是硬扛，而是拆问题。比如设备联调或模型链路出问题时，我会先判断是环境、网络、数据、代码还是模型本身的问题，再逐个排查。这样压力会小很多，也更容易推进。
