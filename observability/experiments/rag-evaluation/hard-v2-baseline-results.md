## 结论边界与下一步

1. 该结果说明当前小规模受控语料上，纯向量对大多数难例已有较好首证据排序；它不证明混合检索或重排已经带来提升。
2. 拒答题的空证据率为 0，说明后续必须引入“证据充分性 / 拒答”门，而不能依赖空检索降级。
3. 实现关键词候选 + RRF + Cross-Encoder 后，必须使用同一语料、同一 Gold、同一 Top-K 再跑本页四项指标；只有 `Recall@5` 不降且 `MRR@10` 或 `nDCG@10` 有可解释提升，才构成优化结论。

## H1：字符三元组 + 向量 + 加权 RRF

2026-08-16 在提交 `154d1f7b88eb60fbf52b60de7be89cbc86a26b5c` 上，以相同知识库 ID 8–19、关闭 Query Rewrite 复跑。词法路使用 PostgreSQL `pg_trgm`，融合公式为加权 RRF：向量权重 3、字符三元组权重 1、`k=60`；SQL 使用距离后追加文档 ID 作为稳定排序键。

| 指标 | V0 纯向量 | H1 混合 + RRF | 变化 |

| Recall@5 | 0.9833 | 1.0000 | +0.0167 |

| nDCG@10 | 0.9686 | 0.9724 | +0.0038 |

稳定排序修复后，H1 连续 3 次得到相同四项质量指标。应用内 Micrometer 阶段计时显示：字符三元组召回 160 次平均 2.023 ms、RRF 融合 160 次平均 0.088 ms；同期向量召回 200 次平均 600.597 ms。批量请求总耗时受远程 Embedding 服务波动影响明显，因此阶段计时比单次批处理墙钟时间更适合描述本地混合检索开销。

### 结论边界

- H1 补回了原基线缺失的 Top-5 金标证据，但 MRR 不变、nDCG 增益很小，当前只能说明混合召回链路有效，不能单独包装成显著优化。
- 3:1 权重是在本套 v2-hard 上观察后确定，属于调参结果，不是独立测试集结论。下一轮必须冻结 dev/test 切分或引入未参与调参的新题，再报告可用于简历的提升。
- 10 条不可回答题仍全部返回候选；拒答必须由证据充分性或回答评测解决，不能依赖“零召回”。
- `HYBRID_RERANK` 已接入 `qwen3-rerank`，但当前环境没有百炼 WorkspaceId，尚无真实 H2 分数；在完成真实调用前不得声称交叉编码器带来提升。
